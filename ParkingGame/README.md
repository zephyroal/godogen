# ParkingGame — 3D 俯视角倒车入库

Godot 4.7.1 (.NET/C#) 停车游戏：真实刚体车辆物理（`VehicleBody3D` + 四轮悬挂/牵引/转向）、
手动挡 R/N/D、6 个难度递进的停车场景、**路上有走动的行人与巡场车**。**入库不由系统自动
判定**——停好后玩家点「报告我停好了」按钮（或按 G），游戏检测并给出结果：成功弹出结算
（用时/碰撞/角度误差/居中偏差，够正则评「★ 完美入库」），失败弹 toast 说明具体原因，
可继续调整后再次报告。

## 运行

```bat
build_scene.bat   # dotnet build + headless 导入 + 生成 scenes/Main.tscn（首次或场景变更后）
run_game.bat      # 编译并启动游戏
run_demo.bat      # 第 1 关自动驾驶演示（无需输入注入的端到端验证）
```

或直接：`"Godot_4.7.1_mono_console.exe" --path <本目录> [-- --demo | --verify-report | --verify-hazards] [-- --level=N]`
（注意：`--` 之后的参数用 `OS.GetCmdlineUserArgs()` 读，`GetCmdlineArgs()` 只有引擎参数）。

## 移动小怪（行人 / 巡场车）

- `Hazard`（`AnimatableBody3D` 运动学体）：行人沿直线路径往返（带行走摆动动画、
  朝向随行进方向平滑转身）；巡场车沿矩形环路行驶（前白后红车灯常亮，被 Glow 拾取）。
- **碰撞语义**：撞上小怪 = 普通碰撞，计入成绩、毁掉「★ 完美入库」评级。
- **阻挡行为**：小怪沿行进方向做短射线探测，被玩家车挡住去路会**停下等待**——
  行人不会把 1.2 吨的车推着走（那是运动学体的物理默认行为，也是这里要避免的）。
- **计数机制**：碰撞统计挂在车上的 `Area3D` 触发器（`Car.OnBodyEntered`）。
  引擎陷阱（实测）：**RigidBody 的 `BodyEntered` 对 kinematic（AnimatableBody3D）
  不产生回调**——行人能物理推动车辆，信号却静默；Area3D 对 static/kinematic/rigid
  全类型都可靠触发。另外 `AnimatableBody3D.SyncToPhysics` 必须保持默认 true，
  否则碰撞器不随节点移动（视觉动了、碰撞体冻在原地）。

## 停车检测与结果（Game.ReportParked / EvaluateParking）

报告按钮、G 键、demo 自动驾驶都汇入 `ReportParked()`，检测事实：

- **四角入库**：车身四角（半长 2.3 / 半宽 0.9）全部在库位 OBB 内（余量 0.04m）；
- **角度**：车身前向与库位长轴 |cos| ≥ cos(容差)；
- **静止**：线速度 < 0.12 m/s；
- 居中偏差 / 角度误差只影响评分展示，不作硬门槛。

结果两分支：

- **成功** → 结算遮罩：用时 · 碰撞 · 角度误差 · 横向居中偏差；
  0 碰撞且角度 ≤5° 且横向偏差 ≤15cm 评「★ 完美入库」，否则「√ 停车入位成功」；
  回车下一关 / 退格重试。
- **失败** → 顶部 toast（4 秒自动消失）逐条说明原因（还在移动 / 只有 N/4 角在库内 /
  夹角 X° 超容差），计时不中断，可继续调整后再报告（1.5s 冷却防连点）。

经验：**真正的瓶颈是四角在库内而不是角度容差**——4.6m 车身在 2.5m 宽库位里，
偏航 >~8° 时对角线超出库宽，15° 容差形同虚设。库得正，才有 inSlot=4。

## 车辆与渲染

- 玩家车：程序化拼装——底盘 + 玻璃窗带 + 车顶 + 前白后红自发光车灯 + 保险杠 + 轮毂，
  清漆质感（Roughness 0.32 / Metallic 0.12）；停放车同款轮廓但灯光熄灭；
  巡场车琥珀色、灯光常亮。
- 行人：胶囊身体 + 球形头部，蓝衣肤色，走路带上下摆动。
- 光照：ProceduralSky 天光环境光 + 暖色太阳（软阴影 `ShadowBlur`）、**SSAO** 接地暗部、
  **Glow** 拾取车灯与自发光库位白线、Filmic 色调映射、**8x MSAA + FXAA** 抗锯齿。
- 引擎陷阱（实测）：Godot 4.7.1 车体级 `EngineForce` 正值推向 +Z（车尾方向），与 Bullet
  文档直觉相反——前进（-Z）用负值，倒车用正值；C# 枚举名是 `Viewport.Msaa.Msaa8X`
  （大写 X）、`Viewport.ScreenSpaceAAEnum.Fxaa`；射线查询 `HitFromInside` 默认 false，
  从自身形状内部发出的射线不会自检命中（小怪前方探测利用了这一点）。

## 车辆物理（Car.cs）

- 质量 1200kg，后轮驱动，轴距 2.96m，满舵 34°（随速度以 16 m/s 线性衰减，下限 30%），
  转向作动器 7/s 速率插值；发动机力低速强、高速衰减（D 3400N / R 2400N）；
  刹车 7.0（经验值），静止捏死时 `LinearDamp=8` 防滑移。

## --demo 自动驾驶（第 1 关）

无输入注入环境下的端到端验证。四阶段状态机（`Game.DemoTick`）：

1. **摆尾弧**：后轴走运动学精确的两段满舵 S（r=4.8m）：甩入 62°（yaw -90→-152）+ 回摆 50°（→-102）。
   追踪用**折线前瞻胡萝卜点 + 精确纯追踪律** δ=atan(2·L·sin(err)/lookahead)——
   比例增益对这种曲率会欠舵 6 倍，车漂出路径、交接欠 40° 航向债；
2. **倒车靠泊**：δ=2.5h+1.1lz 航向/横向闭环（R 挡右舵抬 yaw、左舵送尾向北——实测）；
3. **前拉回正**：D 挡回一把方向（侧方位几何必然带残余航向，单程 S 弧在库位纵向空间内摆不正）；
4. **末段倒回**：停车门限直接用游戏判定（inSlot=4 且 angleOk）——近似几何公式会差 0.01 拒停；
   停稳 0.8s 后提交与真人相同的 `ReportParked()` 报告。

结果落盘 `demo_state.txt`（0.2s 一帧遥测），成功截图 `screenshots/demo_success.png`
后自动退出（exit 0）。当前：**19.9s、0 碰撞、角度 5.2°、横向 8cm，连跑稳定复现**
（第 1 关的散步行人在东侧远端，不经过 demo 轨迹）。

## 脚本化验证（无需输入注入）

- `--verify-report`：判定两条结果路径——传送车到歪姿势→报告→断言失败+截图 toast
  （`report_fail_toast.png`）；等 toast 自动隐藏后传送到完美姿势→报告→断言成功+截图
  结算（`report_perfect.png`）。日志 `verify_report.txt`，exit 0。
- `--verify-hazards`：遍历全部 6 关——每关断言出生零碰撞（抓出生点嵌墙类 bug）、
  小怪确实在移动、截图 `verify_lv{N}.png`；L2 额外断言行人被停着的车阻挡在 ~1.3m 外
  等待（零接触）、重叠传送后 kinematic/static 两类碰撞都正确计数。
  日志 `verify_hazards.txt`，exit 0。

## 工程结构

```
project.godot            # 1280x720、physics 60Hz、SystemFont
scenes/BuildMain.cs      # 打包期生成 Main.tscn（极简根节点，nodes=1 校验）
scenes/Main.tscn         # 生成物（勿手编）
scripts/Car.cs           # VehicleBody3D：挡位/动力/转向/四角 + 程序化车壳 + Area 碰撞触发器
scripts/Hazard.cs        # 行人/巡场车：AnimatableBody3D 往返/环路 + 射线阻挡 + 程序化外观
scripts/Level.cs         # 6 关定义 + 程序化构建（地面/库位线/墙/停车/锥桶/小怪）
scripts/HUD.cs           # 档位/时速/计时/报告按钮/失败 toast/开局与结算遮罩
scripts/Game.cs           # 环境/相机/输入/关卡流转/ReportParked 判定/--demo/--verify-*
```

场景运行时全程序化构建；`Main.tscn` 只是挂 `Game` 的极简壳。
