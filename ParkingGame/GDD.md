# ParkingGame — 游戏设计文档（GDD）

> 3D 俯视角倒车入库模拟游戏 · Godot 4.7.1 (.NET/C#) · 纯程序化构建（无外部素材）
> 本文档是设计基线：实现以此为准，行为偏差以 `--verify-*` 脚本验证结果为准。

## 1. 概述

**一句话**：真实刚体车辆物理的俯视角停车游戏——开过车位、挂 R、摆尾倒进画线库位，
自己判断停好没停好，按「报告我停好了」接受系统判定。

- **类型**：休闲技能挑战 / 停车模拟
- **视角**：固定北向俯视跟随相机
- **单局时长**：15~60 秒/关
- **平台**：Windows（Vulkan），1280×720，60Hz 物理

## 2. 核心循环

```
选关 → 开到车位附近 → 倒车入库（避开行人/巡场车/锥桶/墙）→ 自认为停好
→ 按报告按钮(G) → 系统判定 → 成功：结算+金币+下一关 / 失败：toast 说明原因，继续调整
```

判定**永远由玩家主动触发**——系统不自动判定，玩家必须自己判断（这也是玩法的一部分）。

## 4. 判定与评分

**通过条件**（三项同时满足）：
1. 车身四角（半长 2.3 / 半宽 0.9）全部在库位 OBB 内（余量 0.04m）；
2. 车身前向与库位长轴夹角 ≤ 关卡容差（默认 15°，L6 为 10°）；
3. 线速度 < 0.12 m/s（静止）。

**评分**：成功 =「√ 停车入位成功」+150 金币；0 碰撞且角度 ≤5° 且横向偏差 ≤15cm =
「★ 完美入库」+300 金币。失败 = toast 逐条列出原因（移动中 / N/4 角 / 角度 X°），4s 消失，
可继续调整（1.5s 冷却）。

**几何事实**（关卡设计的硬约束）：4.6m 车身在 2.5m 宽库位里，偏航 >~8° 对角线超宽——
四角入库的真实瓶颈是角度而非 15° 容差。

## 5. 车辆与物理

- 质量 1200kg，后轮驱动，轴距 2.96m，满舵 34°（随速度 16 m/s 线性衰减，下限 30%），
  转向作动器 7/s；动力 D 3400N / R 2400N（低速强高速衰减）；刹车 7.0，静止捏死 LinearDamp=8。
- **引擎符号陷阱**：车体级 EngineForce 正值推向 +Z（车尾），与 Bullet 文档直觉相反。
- **抓地力随天气缩放**：晴 1.0 / 雨 0.78 / 雪 0.55（轮胎摩擦系数整体缩放，雪地操控需更柔）。

## 7. 移动小怪

- **行人**（AnimatableBody3D）：蓝衣胶囊+肤色头，直线路径往返，行走摆动动画；
- **巡场车**：琥珀色，矩形环路，车灯常亮；
- **阻挡**：前方短射线探测——被玩家车挡路时停下等待，不推车（运动学推力对 1.2t 车辆
  的物理推动既不真实也破坏判定）；
- **碰撞**：撞上小怪 = 普通碰撞，计入成绩；行人被挡停在 ~0.65m 个人距离外。
- 计数机制：车上挂 Area3D 触发器（RigidBody.BodyEntered 对 kinematic 不触发，Area 全类型可靠）。

## 8. 天气系统

四种预设，影响天空/环境光/太阳/雾/Glow/粒子/抓地力：

| 天气 | 天空 | 太阳 | 效果 | 抓地 |
|---|---|---|---|---|
| 晴 Sunny | 蓝天 | 暖白 1.35 | 默认 | 1.0 |
| 雨 Rain | 灰蓝 | 冷白 0.6 | 雨丝粒子+轻雾+地面湿感 | 0.78 |
| 雪 Snow | 惨白 | 冷白 0.9 | 雪花粒子缓落 | 0.55 |

## 9. 视效

- **光照**：ProceduralSky + 暖色太阳 + ShadowBlur 软阴影 + SSAO 接地暗部 +
  Glow（强度 0.65，拾取车灯与自发光库位线）+ Filmic + 8x MSAA + FXAA。
- **刹车灯**：踩刹车/拉手刹时尾灯发光能量 1.4→3.2。
- **刹车轨迹**：重刹或手刹滑行时，后轮落点生成暗色四边形（对象池 360，10s 淡出）。
- **爆炸**：碰撞时接触点一次性粒子爆发（橙→灰）+ OmniLight 闪光 + 镜头震动 0.4s。
- 玩家车细节：底盘/玻璃窗带/车顶/前后灯/保险杠/轮毂/清漆；停放车同轮廓灯熄灭。

## 10. 经济与车库

- **金币**：入库成功 +150 / 完美 +300；持久化于 `user://parking_save.json`。
- **涂装**（车库 B 键，开局/结算时可开）：经典红(免费)、曜石黑 200、海洋蓝 300、
  珍珠白 400、荧光绿 600、鎏金 1000。购买后永久拥有，选择即换玩家车漆面。
- 存档字段：coins、owned[]、selected。

## 11. 关卡编辑器（E 键）

- **工具**：1 墙块（R 横竖）· 2 停放车（R 45°步进）· 3 锥桶 · 4 行人（两次点击定路径）
  · 5 库位（R 旋转 / [ ] 长度 / - = 宽度）· 6 出生点 · 7 删除 · W 天气循环 · S 保存 · T 测试 · Esc 退出。
- 鼠标左键在地面放置；虚影预览跟随鼠标；实时重建关卡预览（含移动中的小怪）。
- 保存格式：`levels/custom.json`（墙/停车/锥/行人/库位/出生点/天气全部字段）。
- 测试（T）：直接试玩当前草稿，Esc 回编辑器；保存后开局界面按 0 可随时游玩。

## 14. 打包与 C# 代码保护（结论）

Godot 4 .NET 导出时，C# 程序集以**明文 IL DLL** 放进 PCK，ILSpy/dnSpy 可直接反编译出
接近源码的逻辑。引擎**没有原生的程序集加密**：script encryption key 只覆盖 GDScript
类资源，管不到 .NET 程序集。可行的保护梯度：

1. **混淆**（实用首选）：Obfuscar（免费，MSBuild 集成）重命名符号；商业方案 ConfuserEx2/Babel
   还做控制流混淆。导出前对 DLL 跑一遍混淆即可，游戏运行不受影响。
2. **裁剪 + ReadyToRun**：去掉元数据/IL 直达，提高逆向成本，但挡不住决心大的。
3. **NativeAOT**：真正的原生化保护，Godot 官方 .NET 导出**尚不支持**（GDScript/GDExtension
   才有原生路径），跟踪 Godot 4.x 后续版本。
4. PCK 加密（Export 的 encryption key）保护资源文件本身，但 DLL 仍在其中以 IL 形式存在。

**本项目结论**：单机休闲游戏风险低，暂不接混淆；若发布，导出流程加一步 Obfuscar 即可。
