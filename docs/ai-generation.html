1总体架构：双链路设计

Godogen 本身不是游戏——它是"生成游戏仓库的生成器"源仓库。 publish.sh 把运行时提示（CLAUDE.md/AGENTS.md）、引擎指南（engines/*.md）、 资产生成技能（asset-gen/）发布到目标游戏仓库，由宿主 Agent（Claude Code / Codex / Codely CLI） 实际驱动游戏与资产的生成。

2链路 A：本地 Python CLI（asset_gen.py）

核心 CLI 入口 asset-gen/tools/asset_gen.py，输出契约为 JSON stdout（含 cost_cents）。 支持 6 个子命令：

image — 文生图 / 图生图

Provider模型计费说明
Geminigemini-3.1-flash-image-preview512px=5 分 / 1K=7 分 / 2K=10 分 / 4K=15 分14 种宽高比；图生图需指定 --image
Grokgrok-imagine-image2 分xai_sdk.Client().image.sample()；图生图走 base64 data URI

video — AI 视频生成

  • Grok grok-imagine-video：5 分/秒，支持 1-15 秒，480p / 720p
  • xai_sdk.Client().video.generate() → requests 下载 MP4

glb — 图生 3D 模型

  • default = 30 分（30k 面，standard 精度）
  • hd = 60 分（detailed 精度）
  • 底层调 tripo3d.py（见下节）

rig — 骨骼绑定

  • +25 分，仅支持 biped（两足角色）
  • 先调 animate_prerigcheck 校验 rig_type 合法性

retarget — 动画重定向

  • 10 分/clip，预设体系 preset:biped:*，约 130 个动画预设名
  • bake_animation=true 烘焙到骨骼

resume — 断点恢复

  • 从 sidecar 文件 <output>.tripo.json 恢复超时任务，不重复计费

3Tripo3D 图生 3D 后端

asset-gen/tools/tripo3d.py — 完整 REST API 封装：

API_BASE = https://api.tripo3d.ai/v2/openapi
认证: Bearer TRIPO3D_API_KEY

流程:
POST /upload          → image_token（上传参考图）
POST /task            → { type: "image_to_model",
                          model_version: "v3.1-20260211",
                          face_limit / pbr / geometry_quality / texture_quality }
GET  /task/{id}       → 轮询（600s 超时 / 5s 间隔）
下载 output.pbr_model || model || base_model
  • 骨骼绑定 API：省略 model_version 自动使用 v1.0-20240301
  • 重定向 API：animate_retarget（bake_animation=true）

4链路 B：Codely MCP（TJGenerator / Rodin）

MCP 端点 https://ai-generator.tuanjie.cn/mcp。认证用 oauth_creds.json 的 access_token（⚠️ 不是旧的 mcp-oauth-tokens.json）。 调用需完整 MCP 会话：initialize → notifications/initialized → tools/call， PowerShell 下用 --data-binary @file 避免编码问题。

generate_3d_model — 3D 模型生成

实际路由全部走 Rodin（type=rodin_generation）——传的 provider / model_version 被后端忽略
质量杠杆tier（关键参数）+ texture_mode=high
face_limit映射为 Rodin 的 qualityOverride
产物返回 rodin_base_basic_pbr.glb 的下载 URL
tier耗时质量成本确认
Extreme-Low~40 秒快但糙（适合草稿验证）不需要
Gen-2.5-High3-10 分钟正式产出档必须 confirm_cost=true

⚠ 高成本确认陷阱

Gen-2.5-High 不传 confirm_cost=true 时，返回积分确认提示但 CLI 无法解析，连续报 [Error: Could not parse tool response]——曾连败 5 次误判为服务故障。

generate_image / seedream — AI 绘图

  • frontier 生图服务不稳定（2026-09-01 全天不可用）
  • 降级 seedream 同样可靠——体素风 2048×2048 全过质检
  • 批量提交后连续 parse error 多为提交限流，等 60-120 秒重试

排障绕行方案

💡 provider=rodin 持续 parse error 时的绕行

改传 provider=tripo 可成功派发任务——后端仍实际路由 rodin_generation（tier=Gen-2.5-Extreme-Low, PBR），最终质量相同。 曾用此法成功派发 14 个任务。

⚠ poll_command_powershell 陷阱

工具返回的 poll_command_powershell 内含 function Try—— Try 是 PowerShell 保留字，直接执行必报解析错。 派发轮询子代理时需将函数改名（如 Poll1）。

7GLB 元数据清洗（scrub_glb.py）

根目录 scrub_glb.py — 清洗 AI 生成管线在 GLB/JPEG 中嵌入的厂商元数据：

GLB 清洗

  • 删除 asset.extras 和 scenes[].extras（生成管线的水印标识： {"author": "\"unity\"", "copyright": "\"tjai\"", "watermark_id": "\"\""}）
  • 重建 chunk 长度、紧凑重序列化 JSON（数值无损往返）
  • 带 5 条 assert 校验：总长 / JSON 头 / extras 已删 / BIN chunk 字节不变
  • 幂等：已清洗的文件不重复写入

JPEG 清洗

  • 删除 COM 段（payload 以 MetaWatermark 开头的水印注释）
  • 删除 APP11 段（JUMBF / content-credentials 出处标记）
  • 概念图体积降 ~40%（如 king_red_lp 342KB → 213KB）
# 用法
python scrub_glb.py <dir_or_file>
# 输出 JSON 汇总: [{path, ok, status: clean|scrubbed, removed, old_total, new_total}]

配套 scrub_glb.bat 批处理（纯 ASCII 避开 cmd chcp 65001 解析错位 bug）， 一次清洗 MiniGame + 3DChess 三个目录。

8GLB 接入引擎（AABB 缩放对齐 + 程序化回退）

两个游戏共用同一套 GLB 接入模式——"GLB 优先加载 + AABB 缩放对齐 + 缺失时程序化回退"：

MiniGame — scripts/Glb.cs

  • 按路径缓存 PackedScene（Dictionary<string, PackedScene>）
  • 实例化 → 递归测量全部 Mesh 的合并 AABB（变换全部 8 角点，累积本地 Transform）
  • 按目标高度缩放 + 底部对齐 y=0 + 足迹居中（归一化变换烘焙进实例根）
  • 单层结构：<model>_wrap_N（placement）→ 实例（normalize transform）
  • 文件缺失返回 null → 调用方回退程序化几何
  • 同时提供 ScaledHalfExtents() 给 Fortress 计算城堡足迹占地

3DChess — scripts/Piece.cs BuildFromGlb()

  • 按 (PieceType, Side) 缓存 PackedScene
  • MeasureAabb() — 同样的 8 角点全变换算法（2026-09-02 修复： 原 GetAabb 只变换 min 角点 + 用 GlobalTransform，导致炮/士位置偏移几十单位）
  • 按目标高度 & 底面直径取较小比例缩放
  • 红方 180° 朝向修正（面向黑方）
  • GLB 缺失时回退 BuildProcedural()（圆柱+圆环+球体木质棋子）

10实战踩坑手册

MCP parse error 连续出现

① 检查是否漏传 confirm_cost=true（高成本档）
② 批量提交后可能是限流——等 60-120 秒重试
③ rodin 持续报错改 provider=tripo 绕行

PowerShell 保留字冲突

poll_command_powershell 内含 function Try——PS 保留字，执行必报错。 派发子代理时函数改名（如 Poll1）。

OAuth token 认证错误

必须用 oauth_creds.json 的 access_token—— 不是旧的 mcp-oauth-tokens.json。

音效校验陷阱

"同字节数 ≠ 同内容"——必须 Get-FileHash 比较。时长吸附固定档位，请求值与实际输出可能不符。

概念图透明底

严禁 prompt "transparent background"（AI 画棋盘格）。用纯色底 + rembg 抠图， --preview 出 _qa.png 人工验收。

frontier 生图服务不稳定

不可用时降级 seedream——体素风 2048×2048 全过质检，同等可靠。

MCP 完整会话

必须完整走 initialize → notifications/initialized → tools/call； PowerShell 用 --data-binary @file 避免编码截断。

Tripo3D 超时恢复

resume 子命令从 <output>.tripo.json sidecar 恢复任务， 不重复计费。
